# HOI4 scripting systems

This page is a compact reference for the scripting systems most often generated by this project: events, national focuses, decisions, ideas, and on-actions. Script syntax is version-sensitive; validate identifiers and effects against the target game's files.

## General rules

- Put definitions in the directory expected by the system. File names are usually free-form, but duplicate IDs are not.
- Keep identifiers stable and use a project namespace for events and other globally registered keys.
- Localise every player-facing ID in `localisation/english/*_l_english.yml`.
- Check the active scope before using a trigger or effect. A country, state, province, unit, and character do not expose the same API.
- Use `error.log`, `game.log`, and `text.log` to find parser, scope, and localisation errors.

## Events

Event definitions live in `events/*.txt`. Declare a namespace outside event blocks, then use a namespaced numeric ID:

```pdx
add_namespace = aurora

country_event = {
    id = aurora.1
    title = aurora.1.t
    desc = aurora.1.d
    picture = GFX_aurora_event
    is_triggered_only = yes

    option = {
        name = aurora.1.a
        add_political_power = 25
    }
}
```

Common event types include `country_event`, `news_event`, `state_event`, `unit_leader_event`, and `operative_leader_event`. A triggered-only event is called by an effect; an event with a `trigger` or mean-time-to-happen can be checked automatically.

Useful event fields include `immediate`, `after`, `trigger`, `option`, `timeout_days`, `fire_only_once`, `major`, and `is_triggered_only`. For `state_event`, set the recipient scope with the documented `trigger_for` value when required.

Trigger an event from another script with either a short form or a parameter block:

```pdx
country_event = aurora.1
country_event = { id = aurora.1 days = 3 random_days = 2 }
```

## National focuses

Focus trees are defined in `common/national_focus/*.txt`; continuous focuses use `common/continuous_focus/*.txt`. A tree needs a unique ID, a country-selection block or a `default` setting, and at least one focus:

```pdx
focus_tree = {
    id = aurora_focus_tree
    country = { factor = 0 modifier = { add = 10 tag = AUR } }

    focus = {
        id = AUR_industry
        icon = GFX_goal_generic_construct_civilian
        x = 0
        y = 0
        cost = 10
        completion_reward = {
            add_political_power = 50
        }
    }
}
```

Focuses can use `prerequisite`, `mutually_exclusive`, `available`, `bypass`, `cancel`, `completion_reward`, `ai_will_do`, and `search_filters`. Shared and joint focuses must be defined and referenced using the syntax supported by the target version. Every focus ID, title, description, and icon needs a matching asset or English localisation key.

## Decisions

Decision categories and decisions are defined in `common/decisions/*.txt`; category files may be placed in `common/decisions/categories/` depending on the game version. A category controls visibility and presentation, while each decision supplies its own cost and effects:

```pdx
aurora_decisions = {
    icon = generic_political_pressure
    visible = { has_war = yes }

    aurora_rebuild = {
        icon = generic_construct_civilian
        visible = { has_war = no }
        available = { has_equipment = { infantry_equipment = 100 } }
        cost = 50
        complete_effect = { add_stability = 0.05 }
        days_remove = 30
        ai_will_do = { base = 1 }
    }
}
```

The usual decision lifecycle is `visible` → `available` → `complete_effect`, with optional `modifier`, `days_remove`, `remove_effect`, `cancel_trigger`, and `cancel_effect`. Localise the decision, description, blocked text, and tooltip variants where the UI expects them.

## Ideas and national spirits

Ideas are defined under `common/ideas/*.txt` and are added by country history or scripted effects. An idea typically contains a cost, category, removal rules, and modifiers:

```pdx
ideas = {
    country = {
        aurora_reconstruction = {
            picture = generic_industry
            allowed = { tag = AUR }
            removal_cost = 50
            consumer_goods_factor = -0.05
            production_speed_buildings_factor = 0.10
        }
    }
}
```

The key must be localised, and the idea category must be one accepted by the game. Add or remove ideas using the documented country effects rather than editing generated history after startup.

## On-actions

On-actions live in `common/on_actions/*.txt` and run scripted blocks at engine-defined points. Add events or effects under the correct on-action key and keep the block's active scope in mind. A missing referenced event, malformed block, or invalid scope can fail during loading or the first tick that reaches the action.

## Assets and localisation

Player-facing text belongs in English localisation:

```yaml
l_english:
 aurora.1.t:0 "A New Dawn"
 aurora.1.d:0 "The reconstruction plan is ready."
 aurora.1.a:0 "Begin the work"
```

Event pictures, focus icons, decision icons, and idea pictures need matching `interface/*.gfx` sprite definitions and image assets in `gfx/`. Avoid using an asset path that exists only in the vanilla installation when the MOD is expected to run independently.

## Debugging checklist

1. Search `error.log` for the first parser error rather than the final cascade.
2. Verify IDs, namespaces, scopes, and file paths against the target game version.
3. Confirm every visible key and sprite exists in the English localisation and interface files.
4. Test triggered effects with `tdebug` and a minimal save before integrating them into a large tree.
5. Re-run the export validation after changing states, countries, or map IDs.
